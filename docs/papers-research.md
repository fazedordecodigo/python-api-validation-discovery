# Papers que informam o harness

Esta página lista os trabalhos que a descoberta usa para desenhar o loop de entrega do agente. Continua o cenário Python numa plataforma de dados na AWS. Cada entrada traz título, autores, ano, venue (ou preprint), link e uma linha sobre o que entra neste repositório. Não inventa cifra nem citação. O texto integral de papers IEEE não lidos está marcado.

## Loop e feedback

- **Is Three the Magic Number? An Empirical Evaluation of LLM-Based Repair Loops.** Tobias Kiecker, Eik Reichmann, Hosung Kang, Gabin An, Lars Grunske. 2026. Preprint. https://arxiv.org/abs/2607.05197
  Mantém o teto de 3 voltas. O estudo vê a maior parte do ganho nas primeiras 3 a 4 rodadas; este harness não sobe o limite e registra em qual tentativa passou.

- **PGS: Effective LLM Code Refinement via Property-Oriented and Structurally Minimal Feedback.** Lehan He, Zeren Chen, Xiang Gao, Zhe Zhang, Lu Sheng. Preprint. https://arxiv.org/abs/2506.18315
  O texto que volta ao agente é a propriedade quebrada e o menor contraexemplo, não o log cru da ferramenta. O modelo não é pedido para explicar o próprio erro.

- **Is Self-Repair a Silver Bullet for Code Generation?** Theo X. Olausson, Jeevana Priya Inala, Chenglong Wang, Jianfeng Gao, Armando Solar-Lezama. 2024. ICLR. https://arxiv.org/abs/2306.09896
  Apoia o ponto anterior: a qualidade do feedback é o gargalo do self-repair, não só mais uma volta.

- **RepairAgent: An Autonomous, LLM-Based Agent for Program Repair.** Islem Bouzenia, Premkumar Devanbu, Michael Pradel. 2024. Preprint. https://arxiv.org/abs/2403.17134
  O harness hasheia a falha (ferramenta + mensagem normalizada + check). Se o mesmo hash volta, descarta o patch e aborta aquela linha. Patch que falhou é revertido antes da próxima tentativa.

## Fechar a tarefa e espessura da suíte

- **SWE-bench: Can Language Models Resolve Real-World GitHub Issues?** Carlos E. Jimenez, John Yang, Alexander Wettig, Shunyu Yao, Kexin Pei, Ofir Press, Karthik Narasimhan. 2024. ICLR. https://arxiv.org/abs/2310.06770
  A tarefa só fecha quando os checks que tinham de passar passam e os que já passavam continuam passando (fail-to-pass e pass-to-pass).

- **Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation.** Jiawei Liu, Chunqiu Steven Xia, Yuyao Wang, Lingming Zhang. 2023. Preprint. https://arxiv.org/abs/2305.01210
  Suíte fina não basta. Mais casos baixam o pass@k e podem mudar o ranking. Este repositório não roda EvalPlus. O extra local é o Schemathesis gerando casos a partir do OpenAPI e o pytest da regra nomeada, não um clone desse benchmark.

- **Are “Solved Issues” in SWE-bench Really Solved Correctly? An Empirical Study.** You Wang, Michael Pradel, Zhongxin Liu. 2025. Preprint. https://arxiv.org/abs/2503.15223
  Patch que passa numa suíte fina ainda pode falhar na suíte de quem mantém o código. O abstract reporta inflação da taxa de resolução em 6,4 pontos percentuais absolutos. Não feche no primeiro verde fino.

## Propriedade e vizinhança

- **Agentic Property-Based Testing: Finding Bugs Across the Python Ecosystem.** Muhammad Maaz, Liam DeVoe, Zac Hatfield-Dodds, Nicholas Carlini. 2025. Workshop NeurIPS 2025. https://arxiv.org/abs/2510.09907
  Para regra nomeada que o OpenAPI não cobre, o agente pode inferir uma propriedade a partir do cenário pytest-bdd, gerar um teste de propriedade e só gastar uma volta de correção se uma segunda leitura confirmar que a falha é bug de verdade. Isso não substitui o Schemathesis.

- **Turbulence: Systematically and Automatically Testing Instruction-Tuned Large Language Models for Code.** Shahin Honarvar, Mark van der Wilk, Alastair F. Donaldson. 2025. IEEE ICST. https://ieeexplore.ieee.org/document/10989005
  Só o abstract foi lido. Antes de fechar, rode de novo a mesma propriedade num input vizinho. Passar no primeiro exemplo verde não basta. Este texto não afirma mais do que o abstract.

## Nota (texto integral não lido)

- **Enhancing LLM Code Generation: A Systematic Evaluation of Multi-Agent Collaboration and Runtime Debugging for Accuracy, Reliability, and Latency.** Nazmus Ashrafi, Salah Bouktif, Mohammed Mediani. 2025. IEEE AICT. https://ieeexplore.ieee.org/document/11268754
  Só o abstract foi lido. Ele reporta ganho em HumanEval na combinação estudada pelos autores. Este harness não monta comitê multi-agente a partir desse paper.
